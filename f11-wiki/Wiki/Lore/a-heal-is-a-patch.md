# A Heal Is A Patch

The fixbots' heal skill repairs the code of the entity being fixed, which is why they can mend a robot and heal a person - and why they are the only characters who can see a retcon happen.

**Canon:** proposed · **Era:** always true; discovered in play

## The Story

**A fixbot's heal is not medicine and not repair. It is a patch.** The skill edits the **code of the
entity being fixed**, which is why the same ability mends a broken robot and closes a wound on
[[ninja]]. To something that works at that level, a person and a machine are the same kind of object.

The factions have ten different fictional excuses for healing and respawning ([[death-and-return]]),
and this is the only one that is **literally true about the game the player is holding.** The Robots'
explanation is not a metaphor that happens to be apt; it is the mechanism, stated plainly, in a realm
nobody thinks to take literally.

## What It Costs Them

**They can see the retcons happen.** Everyone else absorbs a rewrite and carries on as though the new
continuity was always the case — that is [[the-retcon-engine]] working correctly, and it is total.
A fixbot reads code, so the change is visible to it as a change ([[continuity-glitches]]).

This makes the [[robots]] the only faction whose **core verb is also the game's detection
instrument**. Repairing things is how they progress, and repairing things is how they notice that
the world is being edited underneath them.

**And it explains the game's cruellest limitation.** Fixbots **cannot repair themselves**
([[no-machine-repairs-itself]]). A machine that can audit any code but its own is exactly the wrong
tool to be holding when the question becomes *is my own memory of this correct?*

## Who Notices What

Seeing a glitch, understanding it, and trusting yourself about it are three different things, and no
character has all three:

| | Sees it | Understands it | Can trust itself |
|---|---|---|---|
| [[autofix]] | **yes** — code sight | no — barely been running | yes, and it does not help |
| [[odie]] | **yes** — code sight, plus a memory that predates the retcons | no — dormant almost the whole time | yes |
| [[mifix]] | **yes** — code sight | partly | **no** — he has run too long and knows his own code is degraded |
| The liches | **yes** — AI self-awareness | **yes**, and they explain it | yes |
| [[gargoyle]] | **yes** — an unedited memory, not code sight | no | yes |
| Everyone else | no | — | — |

**[[mifix]] is the tragedy of it.** He is the one with enough self-awareness to reason about what he
is seeing, and the one who has been running long enough that he **cannot trust his own code** — a
conclusion the wiki already reached from the other direction, since his memory is corrupted and the
reasons have decayed into myth. He is right not to trust himself, he is right about the glitches, and
he has no way to tell those two apart. `no-machine-repairs-itself` means he can never resolve it
alone.

**[[odie]] is the control case.** Switched off deliberately, so his memory predates the retcons and
his code never degraded — code sight *and* an unedited past, with no framework to interpret either.
He and [[gargoyle]] are preserved by the same mechanism from opposite ends of the map.

## Design Consequence

**In-fiction witnesses are a deniability shield.** The standing risk with [[continuity-glitches]] is
a player reading one as a real bug rather than a clue. A glitch that a character *remarks on* cannot
be misread that way — the game has acknowledged it.

So **strong-tier glitches are safest wherever a fixbot or a lich is present**, and that is a
scheduling tool rather than a detail: it means the loudest evidence can be spent in the Robots'
chapters and around the liches, and must be spent more carefully everywhere else.

## Player-Facing

**Available from chapter one, and unreadable until much later.** [[autofix]] leads
[[chapter-01]] and can already see the seams; he simply has no idea what they mean. The player is
handed a character who notices, cannot interpret, and does not think it is important — which is the
ideal way to plant evidence that has to keep for eight chapters.

**Open:** whether the heal-is-code-repair fact is ever stated outright, or only ever shown. Stating
it is a large reveal — it is a straight line from there to *the world is software* — so it probably
belongs on [[the-revelation-schedule]] rather than in a tooltip.
